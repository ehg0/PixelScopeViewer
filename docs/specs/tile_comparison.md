# タイル比較モード 仕様

既存の複数画像比較（`ui/tiling/`、別 window）を撤廃し、メイン画面をグリッドに分割して複数の画像を同期表示するモードに置き換える。

## 1. 用語

| 用語 | 意味 |
|---|---|
| 1 枚表示 | 今のメイン画面の表示（画像 1 枚） |
| タイル比較モード | メイン画面をグリッドに分割して表示するモード |
| グリッド | タイルの並び（行数 × 列数）。最大 4×4 |
| マス | グリッド上の位置 (行, 列)。登録内容はマス単位で持つ |
| タイル | 表示中のマス。タイトル行・画像・ステータス行を持つ枠 |
| 登録リスト | マスに登録した画像の並び（画像 id のリスト） |
| 表示位置 k | n / b で進める、全タイル共通の index |
| active タイル | 最後にクリックしたタイル。1 枚分の情報を出す機能はこのタイルを対象にする |

## 2. モードの切り替え

- 機能（Shift+T）を ON にするとメイン画面がタイル比較モードになり、OFF にすると 1 枚表示に戻る。行き来しても登録内容は保持する。
- 初めて ON にしたときは登録ダイアログを開く。cancel したら 1 枚表示のままにする。
- 登録ダイアログはいつでも開き直せる。
- zoom 倍率と表示中心は、モードを切り替えても引き継ぐ。初めてタイル比較モードにしたときだけ fit する。

## 3. 登録ダイアログ

- **表示する内容**
  - 読み込み済みの画像の一覧
  - グリッドの選択（最大 4×4。選べるサイズと初期値は `defaults.py`）
  - グリッドの各マスの登録リスト
- **登録**：画像一覧からマスへ drag & drop する。同じ画像を複数のマスに登録してよい。
- **編集**
  - マス内の登録リストは drag で並べ替えられ、Delete キーで 1 件ずつ削除できる。
  - マスごとのリセットボタンで、そのマスの登録リストを空にする。
  - 全リセットボタンで、全マスの登録リストを空にする。
- **開き直したとき**：今の登録状態を表示し、そこから追加・編集を続けられる。
- **グリッドを小さくしたとき**
  - 外れたマスの登録は消さずに残し、グリッドを広げると元の位置に戻る。
  - 表示していないマスに登録があるときは「表示していないタイルに登録があります（n 個）」と表示し、まとめて消すボタンを添える。

## 4. 表示

### 4.1 タイル
- 各タイルは「タイトル行（ファイル名）・画像・ステータス行（カーソル位置の画素値）」で構成する。
- タイル i には、そのマスの登録リストの k 番目の画像を表示する。
- k 番目がないタイルは空欄にする。タイトル行は「（なし）」、画像部分は背景色だけにする。
- 画像サイズが違うタイル同士は、画像座標の左上をそろえる。
- active タイルは枠に色を付けて区別する。

### 4.2 画像送り（n / b）
- 全タイルの表示位置 k を一緒に進める・戻す。
- 一番長い登録リストを基準にして、端まで来たら反対の端へ戻る（一周する）。

### 4.3 表示領域の同期
- zoom 倍率と表示位置（画像座標）は全タイルで共通にする。どのタイルで操作しても全タイルに反映する。
- fit は、表示中の画像の最大の幅・高さを基準にする。

### 4.4 明るさ
- タイル比較モードでは、dtype に関わらず全タイルで値を共通にする。
- 保存先は `brightness_by_dtype["tile"]`。初期値は、初めてタイル比較モードにしたときの最初のタイルの画像の dtype の初期値にする。
- 明るさダイアログの slider 範囲は、登録されている画像の dtype の範囲をすべて含む幅にする。
- 明るさダイアログのヒストグラムは、active タイルの画像を表示する。

### 4.5 Auto Scale（確実に動くことを重視する）
- active タイルの画像で計算する。「Use Current ROI」が ON なら、その画像の ROI 内で計算する。求めた値は全タイルに共通で反映する。
- 次のときに計算し直す。
  - ROI の変更
  - channel の表示 ON/OFF の変更
  - n / b
  - active タイルの変更
  - モードの切り替え
- 計算は core の純粋関数にして、単体テストを書く。
- **計算できないときの動き**
  - ROI が画像の範囲外で、切り出した配列が空になる場合は、直前の値を引き継ぐ（値を変えない）。ROI の一部だけが画像の範囲内にある場合は、その部分で計算する。
  - 有効な値がない場合（float の全 NaN など）も、直前の値を引き継ぐ。
  - どちらの場合も例外にしない。
  - この空の配列への対策は、1 枚表示にも同じように効く（今のコードでも、ROI を残したまま小さい画像に切り替えると起こり得る）。
- active タイルが空欄のときは計算しない。

### 4.6 ナビゲーター
- 各マスの縮小画像をグリッドのまま並べて表示し、全マスに表示範囲の枠を描く。
- 縮小倍率は表示中の画像の最大の幅・高さで共通にする。こうすると枠の位置と大きさが全マスでそろう。
- クリック・drag による表示位置の移動は、どのマスからでも同じように動く。

### 4.7 ステータスバー
- **メインのステータスバー**：タイル共通の情報（カーソルの画像座標・ROI・明るさ・zoom 倍率）。
- **各タイルのステータス行**：カーソル位置の画素値。カーソルを置いたタイル以外も、同じ座標の値に更新する。

## 5. ROI

- 編集中 ROI と ROI 一覧（複数 ROI）は全タイル共通にする。どのタイルで作成・移動・リサイズしても全タイルに同じ画像座標で描く。
- 移動・リサイズするときの範囲制限は、操作したタイルの画像サイズに合わせる。
- 範囲外にはみ出した ROI は、そのタイルの解析対象から外す。

## 6. 解析ビュー

- **対象**：表示中の全タイル（空欄のタイルは除く）× ☑ の付いた ROI × 表示 ON の channel。
- **曲線のラベル**：`T{i} R{id} C{k}`。i は今のグリッドでの行優先の番号（1 始まり）。1 枚表示では今と同じ `R{id} C{k}` のまま。
- **色**：今のパレットを循環させる。ラベル単位で個別に再設定できる（`roi_color_overrides` を使う）。
- **Overlay**：すべての曲線を 1 つのグラフに重ねる。
- **Split**：単位を切り替えられる。
  - ROI ごと：1 つのグラフに、その ROI の全タイル分を重ねる。
  - タイルごと：1 つのグラフに、そのタイルの全 ROI 分を重ねる。
- 編集中 ROI の解析（Active）は、全タイル分の曲線を重ねる。
- **メタデータ tab**
  - 表の列をタイルにして、各タイルの値を横に並べる。値がタイル間で違う行は強調表示する（今の複数画像比較のメタデータ一覧と同じ仕様）。
  - 列の見出しは `T{i}: ファイル名`。空欄のタイルは列に含めない。

## 7. drag & drop

- **タイルの上に drop**：画像一覧に追加したうえで、そのマスの登録リストの末尾にも追加する。複数の値を返す loader の画像は、その全部を追加する。
- **タイルの外に drop**：画像一覧に追加するだけにする。

## 8. 1 枚分の情報を使う機能（active タイルを対象にする）

| 機能 | タイル比較モードでの動き |
|---|---|
| 明るさダイアログのヒストグラム・Auto Scale | active タイルの画像（4.4・4.5） |
| 特徴量ダイアログの「今の画像」 | active タイルの画像 |
| ROI のコピー（Ctrl+C） | active タイルの画像 |
| 画像を閉じる | active タイルの画像を閉じ、全マスの登録リストからもその id を消す |
| 画像メニューでの画像の選択 | 選べないようにする（一覧の表示だけ） |
| 状態のコピー（collect_state） | 登録内容・グリッド・k・active タイルも含める |

## 9. 実装方針

### 9.1 `current_index` は「active な画像」の意味のまま残す
タイル比較モードでは、active タイルの画像の index を `current_index` に入れる。こうすると、明るさダイアログ・特徴量・ステータスバーの 1 枚分の処理を直さずに動かせる。直すのはタイル比較モードで動きが変わる箇所だけにする。

### 9.2 画像 id
- 画像の dict に、変わらない id を持たせる。
- 登録リストは id で持つ。画像を閉じても index のずれで壊れない。

### 9.3 `core/tile_layout.py`（Qt 非依存、単体テストあり）
- 16 マス分（4×4）の登録リストを位置 (行, 列) で固定して持つ。グリッドは、その左上から何行・何列を表示するかだけを決める。
- 表示位置 k と一周の計算、マスに表示する画像 id、非表示マスの登録の数、画像 id の削除を持つ。

### 9.4 ImagePane
- タイトル行 + scroll_area + ImageLabel + ステータス行をまとめた部品。1 枚表示では pane 1 つで、タイトル行とステータス行を隠す。mixin は使わない。
- 移行のため、`viewer.scroll_area` と `viewer.image_label` は active な pane のものを返す property にする。navigator・display_info・zoom_manager は、まずそのまま動かしてから 1 つずつタイル対応にする。

### 9.5 描画サイズの統一と scroll の同期
- 各 pane の ImageLabel の大きさを「表示中の画像の最大の幅・高さ × 倍率」にそろえ、画像を左上に描いて余りは背景色にする。
- こうすると全 pane の scrollbar の値が同じ数値になるので、同期は値をそのままコピーするだけで済む（再入を防ぐ flag は立てる）。
- 描画サイズをそろえないと、小さい画像の scrollbar が上限で止まり、その止まった値が他の pane に伝わって大きい画像まで引き戻される。

### 9.6 ROI の持ち主は `state.roi` だけにする
- ImageLabel が持つ widget 座標の `roi_rect` をやめ、各 pane は `state.roi`（画像座標）を読んで描く。
- どの pane で操作しても `state.roi` を書き換えて全 pane を更新するだけにする。

### 9.7 表示用の cache
- 画像 id ごとに、表示設定を key にした QPixmap で持つ。
- 容量の上限付きの LRU にする。上限値は `defaults.py` で管理する（`TILE_DISPLAY_CACHE_MB`）。
- 明るさの slider を動かしている間は、active タイルだけ即座に描き直し、残りのタイルは操作が止まってから描き直す（間引く間隔も `defaults.py`）。

### 9.8 解析ビューの入力を「画像の一覧」に広げる
- `AnalysisDialog` に配列を 1 つ渡す形から、`sources: [(タイルのラベル, 配列, path)]` を渡す形に変える。1 枚表示はラベルなしの source 1 つにする。
- Active（編集中 ROI の解析）は、編集中 ROI を仮の ROI 1 件として同じ処理に通し、処理を 1 本にまとめる。
- メタデータの比較表は、`ui/tiling/comparison_dialog.py` の `_build_comparison_table` を解析ビュー側へ移す。

### 9.9 明るさ
- 保存先のキーを決める関数を 1 つ作り、`"tile"` か dtype 名を返す。
- slider 範囲をすべての dtype を含む幅にする計算と、Auto Scale の min・max の計算は、core の純粋関数にする。

### 9.10 `defaults.py` で管理する値
- `TILE_GRID_SIZES`：選べるグリッド。最大 4×4
- `TILE_GRID_SIZE`：グリッドの初期値
- `TILE_DISPLAY_CACHE_MB`：表示用の cache の容量の上限。初期値 512
- `TILE_BRIGHTNESS_DEBOUNCE_MS`：明るさの変更で、active 以外のタイルを描き直すまでの間隔
- `TILE_REGISTER_DIALOG_SIZE`：登録ダイアログの大きさ
- 古い複数画像比較の `TILING_*` と `TILE_SELECTION_DIALOG_SIZE` は削除する

## 10. 撤廃するもの

- `PixelScopeViewer/ui/tiling/`（全体）。ただし、メタデータの比較表の処理は先に移す（9.8）
- `viewer.py`：`show_tiling_comparison_dialog`、`_tiling_dialog` と、`collect_state`・`closeEvent` の関連処理
- `menu_builder.py`：「複数画像比較」（Shift+T）。新しいモード切り替えに割り当て直す
- `help_dialog.py`：Shift+T の説明
- `ui/analysis/dialog.py`：TilingAnalysisDialog のための分岐（95 行目・213 行目付近）
- `ui/analysis/tabs/common.py`：381 行目付近の、複数画像比較向けの構造の前提
- `ui/common/defaults.py`・`theme.py`：複数画像比較専用の定数（共有している `OVERLAY_PALETTE` は残す）
- `ui/analysis/overlay.py`：docstring の tile についての記述
